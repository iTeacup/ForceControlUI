# ForceControlUI 下载、编译与使用

本项目目前使用 **Windows x64 + Visual Studio 2022 + Debug x64**。仓库已经包含构建需要的公共代码、配套业务 DLL、默认配置和 NOKOV SDK 接口文件，下载后无需再向原开发电脑索取这些文件。

## 1. 下载项目

仓库地址：[iTeacup / ForceControlUI](https://github.com/iTeacup/ForceControlUI)。

网页下载步骤：

1. 打开仓库，选择 `main` 分支。
2. 点击绿色 **Code → Download ZIP**。
3. 在资源管理器中将 ZIP 全部解压，例如解压到 `D:\Projects\ForceControlUI-main`。
4. 不要在压缩包内部打开解决方案。

也可以使用 Git：

```powershell
git clone https://github.com/iTeacup/ForceControlUI.git
```

下载后的结构为：

```text
仓库根目录\
├─ README.md
├─ docs\下载编译与使用.md
└─ ForceControlUI\
   ├─ bus_server\                32 位总线程序、配套 DLL 和总线配置
   ├─ deps\nokov\                当前配套 NOKOV SDK
   ├─ lib64\                     链接库
   ├─ runtime\                   x64 业务 DLL（含通信 DLL）
   ├─ share\、include\、deps\     公共代码和其他依赖
   └─ msvc\
      ├─ ForceControlUI.sln
      ├─ RuntimeFiles.targets    编译后复制运行文件的公共规则
      ├─ ForceControlUI\uicfg.json
      ├─ NokovServer\nokovcfg.json
      ├─ OptServer\optcfg.json
      └─ SRISensorServer\sricfg.json
```

仓库根目录内部还有一层 `ForceControlUI` 工程目录，注意区别。

## 2. 准备 Visual Studio

1. 安装 Visual Studio 2022。
2. 在 Visual Studio Installer 中勾选 **“使用 C++ 的桌面开发”**。
3. 确认包含 **MSVC v143 x64/x86 工具**及 **Windows 10 或 Windows 11 SDK**。

业务依赖采用现有预编译版本，建议使用与项目兼容的较新 VS 2022 v143 工具集。本机验证环境使用 MSVC 14.44。

Debug 程序需要配套的 C++ 调试运行库，由上述开发环境安装。只安装普通 VC++ Redistributable 不能代替该环境。运行软件时无需一直打开 Visual Studio。

## 3. 编译

1. 打开 `ForceControlUI\msvc\ForceControlUI.sln`。
2. 顶部选择 **Debug / x64**。
3. 点击 **生成 → 生成解决方案**。
4. 在“输出”窗口确认四个项目均生成成功。

首次编译后会自动创建 `ForceControlUI\bin64`，包含：

```text
bin64\
├─ ForceControlUId.exe
├─ NokovServer.exe
├─ OptServer.exe
├─ SRISensorServer.exe
├─ cpsapi.dll、libbus.dll
├─ rtded.dll、boost_thread-vc143-mt-gd-x64-1_88.dll
├─ modbus-5.dll、NatNetLib.dll、nokov_sdk.dll
└─ uicfg.json、nokovcfg.json、optcfg.json、sricfg.json
```

这里的 `ForceControlUId.exe` 末尾 d 表示 Debug。**不需要手工复制 DLL、创建 JSON，也不需要把 SDK 放到某个用户名的桌面。**

默认配置只在目标文件不存在时复制。已有 bin64 配置不会被再次编译覆盖；需要查看新模板时，打开各工程目录中的 JSON 并按需调整运行配置。

所有项目已设置调试工作目录为输出目录。使用 Visual Studio 调试时，可右键 ForceControlUI 项目，选择“设为启动项目”，再按 F5。

当前上位机的 Release 配置仍需要另外配套的 `libUI.lib`，本教程统一使用已有依赖支持的 Debug x64。

## 4. 启动软件

### 4.1 启动总线和上位机

1. 进入 `ForceControlUI\bus_server`，双击 `bus_server.exe`，保持运行。
2. 进入 `ForceControlUI\bin64`，双击 `ForceControlUId.exe`。
3. 在“应用”菜单打开要使用的窗口。

同一电脑启动一个总线实例即可。默认总线地址为 `127.0.0.1:4000`。`bus_server` 保留在原目录启动，其配置不会复制到 bin64。

### 4.2 使用 NOKOV

仓库提供了客户端 SDK，实际采集仍需要相机、相机网络、XINGYING 软件及本设备的工程和标定文件。

1. 在 XINGYING 中确认能看到相机和标记点，资产已创建并命名。
2. 在“数据广播”中选择实际网卡，开启 SDK。
3. 打开 `bin64\nokovcfg.json`，将 `nokov.server_ip` 改为 XINGYING 数据广播选中的实际网卡 IPv4 地址。
4. 保持总线运行，启动 `bin64\NokovServer.exe`。
5. 打开上位机 NOKOV 窗口，点击 **连接NOKOV**。
6. 确认设备在线、动捕已连接，能够看到点名称、XYZ 和接收 Hz。

`10.1.1.198` 是配置模板中的示例网卡地址，其他电脑按实际环境修改。`bus.ip` 的 `127.0.0.1` 表示本机总线，两者用途不同。

NOKOV 服务启动后等待 UI 发起连接，不会自动连接动捕。只使用 BLE 等其他窗口时，无需启动 XINGYING 和 NokovServer。

### 4.3 使用 BLE 四通道应变

1. 确认电脑蓝牙可用，PCB 已烧录配套固件并通电。
2. 打开“蓝牙监控”，核对广播名与 UUID，点击 BLE 连接。
3. 确认四路电压和接收 Hz 正常，再开始采集。

01 号板示例：

| 参数 | 内容 |
| --- | --- |
| 广播名 | nRF52840_01 |
| Service UUID | 19B10100-E8F2-537E-4F6C-D104768A1214 |
| Characteristic UUID | 19B10002-E8F2-537E-4F6C-D104768A1214 |

PCB、烧录固件及设备的校准资料由硬件使用者准备。当前 BLE 保存文件只有四路电压，BLE 与 NOKOV 仍是独立采集，尚未实现联合时间对齐。

### 4.4 使用 OPT 或力传感器

默认配置已自动放到 bin64。使用对应硬件前修改 `optcfg.json` 中的地址，或 `sricfg.json` 中的串口等参数，再启动对应服务。不使用的服务无需启动。

## 5. 保存与退出

NOKOV 支持单次保存和连续采集。全选与逐点选择联动，采集中锁定选择。停止后等待后台完成写入，再退出软件。

从 bin64 启动并使用默认保存目录时，每次保存产生：

```text
bin64\data\nokov\NOKOV_编号\data.csv
bin64\data\nokov\NOKOV_编号\marker_map.json
```

异常时可能另有 `error.json`。CSV 中的 frame 使用 SDK 原帧号，time_s 从本轮首个保存帧起算，单位秒；坐标单位 mm。

BLE 文件名为 `ble_device_编号_日期_时间.txt`，位于程序工作目录。采集结果、编译产物及个人运行配置保留在本地，不纳入 Git。

## 6. 文件组织与更新

- `runtime` 保存 x64 业务 DLL，包括 x64 通信 DLL。`bus_server` 自身为 32 位程序，使用其目录中的独立配套 DLL；同名文件不能互换。
- `deps/nokov` 保存当前配套 SDK 的头文件、链接库及 DLL。
- 各工程目录中的 JSON 是版本管理下的默认配置。
- `bin64` 是自动生成的运行目录，继续在 .gitignore 中忽略。

用 Git 下载的用户，关闭程序、妥善保存源码修改后，在仓库根目录执行：

```powershell
git status
git pull --ff-only origin main
```

然后重新生成解决方案。更新业务 DLL 时会自动复制；已有运行配置仍保留，按需对照新模板修改。

用 ZIP 下载的用户重新下载、解压并编译，迁移自己的配置和数据。ZIP 目录没有 Git 历史，不能直接 git pull。

## 7. 常见问题

| 问题 | 处理方式 |
| --- | --- |
| VS 找不到 v143 或 Windows SDK | 在 Visual Studio Installer 中补装 C++ 桌面开发组件 |
| 找不到 MSVCP140D.dll、ucrtbased.dll 等 | 安装配套 VS 2022 C++ 环境，不要从其他电脑手抄系统调试 DLL |
| 找不到业务 DLL 或默认 JSON | 确认当前源码包含 runtime 和 RuntimeFiles.targets；生成对应项目，检查输出窗口的复制错误 |
| 找不到 NOKOV SDK | 确认 deps/nokov 目录完整；如曾设置外部 NokovSdkDir，清除或更新该覆盖值 |
| Release 找不到 libUI.lib | 改用当前已支持的 Debug x64 配置 |
| 提示无法覆盖 EXE/DLL | 先正常停止采集并关闭占用该文件的程序，再生成 |
| 总线启动后退出 | 检查是否重复启动或 4000 端口被占用；从 bus_server 目录运行以保留错误输出 |
| 服务在线但没有点 | 检查 XINGYING SDK 开关、网卡地址、资产和靶标可见性 |
| 已收到帧，本帧为空帧 | 已收到帧但该帧没有可用点，检查动捕输出 |
| 更新配置模板后运行地址没变 | 编译不会覆盖个人配置，修改 bin64 中的对应 JSON |

新电脑的硬件连接和配置仍需按实际环境完成；仓库解决的是构建及软件运行依赖，无需再向原电脑单独索取 DLL 和默认配置。
